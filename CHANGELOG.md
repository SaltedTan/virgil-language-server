# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Server and VS Code extension versions are independent; see [docs/compatibility.md](docs/compatibility.md).

## [Unreleased]

### Added

- Member completion after `.` (`textDocument/completion`), in open documents of configured projects, including unsaved buffers and code that doesn't parse yet. It offers the members that the type checker accepts for the receiver's type, and only those: fields and methods through the class hierarchy, with type arguments substituted and private members only in their file, constructors, a component's members, variant and enum cases, `tag` and `name`, enum sets, layouts, tuple elements, and the builtin members of arrays, ranges, and number types. The receiver can be any expression or a type's name. The server now declares `.` as a completion trigger character, and a `.` in a comment, a literal, or after a number gets an empty list at once. See [Member completion](docs/architecture.md#member-completion) for the lookup rules, the builtin list, the reply, and measurements, and [Known limitations](docs/known-limitations.md#member-completion).
- Completion of the declarations in scope (`textDocument/completion`), in open documents of configured projects, including unsaved buffers and code that doesn't parse yet: locals, parameters, members of the receiver's class and the classes it extends, the file's top-level declarations, type parameters, types, enum and variant cases in match patterns, and `this`, as the type checker sees them at the cursor, nearest first, before the keywords. Code that doesn't parse gets one repair at the cursor, chosen from the cursor's context, as [ADR-0006](docs/decisions/0006-incomplete-code-repair.md) decided. Each completion runs its own analysis of the project, which takes turns with the projects' analyses and renames, and a newer request replaces one that waits. See [Completion](docs/architecture.md#completion) for the scope rules, the repair, scheduling, order, and limits, and [Known limitations](docs/known-limitations.md).
- Keyword completion (`textDocument/completion`) in open documents, from their current text alone, so it works while a file fails to parse and needs no project. A cursor scanner that lexes comments, strings, and byte literals as Aeneas does finds the identifier being typed, member access after `.`, the open delimiters, and the syntactic position, and the server offers the keywords of the pinned compiler that can start there, with the project's language options. See [Completion](docs/architecture.md#completion) for the positions, the reply, and editor setup, and [Known limitations](docs/known-limitations.md) for what it doesn't offer yet.
- A development `repair` command and a corpus of 45 typing states that measure repairing incomplete code at the cursor for semantic completion. [ADR-0006](docs/decisions/0006-incomplete-code-repair.md) records the results and the decision: semantic completion will use the narrow repair at the cursor, and error-tolerant parsing stays in M6.
- Rename (`textDocument/rename`) and prepare rename (`textDocument/prepareRename`) from open documents in configured projects, including unsaved buffers, with versioned edits across open and closed files and a preflight that checks bindings. The Neovim configurations now declare support for versioned edits. See [Rename](docs/architecture.md#rename) for the rules, refusals, and measurements, and [Prepare rename](docs/architecture.md#prepare-rename) for what can be renamed.

### Fixed

- Parsing no longer takes time quadratic in the number of nested expression lambdas, or of simple-body methods and `[]` members on one line ([coordinates](docs/architecture.md#coordinates)).
- Speed up analyses, diagnostics, and requests when a workspace's file names hash alike by using ordered maps for path and URI lookups, with ordinary workspaces as fast as before. See [Maps keyed by path or URI](docs/architecture.md#maps-keyed-by-path-or-uri) for measurements and remaining hash maps.
- Speed up parsing project files whose project names or member keys hash alike, which took time quadratic in their number, by keeping the names and keys in ordered maps. Diagnostics and accepted configurations are unchanged. See [Project files](docs/architecture.md#project-files-partly-present) for measurements.
- Correct in-scope completion in variant case headers and lambda bodies ending with prefix `++` or `--` ([scope rules](docs/architecture.md#names)).

## [0.1.0-alpha.1] - 2026-10-20

### Added

- Signature help (`textDocument/signatureHelp`) for resolved calls in configured projects, including unsaved buffers. See [Signature help](docs/architecture.md#signature-help) for cursor selection, client capabilities, freshness, and incomplete-call limitations.
- Analyses now export the [call sites](docs/architecture.md#call-sites) used by signature help. The development `analyze --display` command prints them. See ADR-0004 for the worker protocol's [layout](docs/decisions/0004-analysis-worker-process.md#channel-and-framing) and [result-budget measurements](docs/decisions/0004-analysis-worker-process.md#supported-program-size).
- Find references (`textDocument/references`) for configured projects, including unsaved buffers and closed files: a use or a declaration's name selects the declaration, and the reply lists its uses in the document's active project, in order of path and position, with its name if `includeDeclaration` is set. A declaration with more references than a reply can hold gets `RequestFailed` rather than a partial list. See [References](docs/architecture.md#references) for coverage, freshness, and reply limits.
- [Known limitations](docs/known-limitations.md) of the alpha, and a [manual test matrix](docs/manual-testing.md) of editor setups, platforms, and features, with what the automated editor tests cover and the results for `0.1.0-alpha.1`. The bug report form now asks for the project file, the archive manifest or source revision, the platform where the server runs, and the server log, and says where each editor shows it.
- Workspace symbols (`workspace/symbol`) now search declarations from configured projects' completed analyses, including unused declarations. See [Workspace symbols](docs/architecture.md#workspace-symbols) for coverage, freshness, ordering, and limits.
- Document symbols now list a variant's cases, including the default case `_`, as its children in source order, with their own fields and methods; a data type stays one symbol. Each symbol carries its declaration's signature as `detail` when the document's active project has an analysis of exactly its current text, and none otherwise; the outline never waits for an analysis. Declaration kinds map to LSP symbol kinds in one place, which `workspace/symbol` shares. See [Document symbols](docs/architecture.md#document-symbols) for the kind mapping and when details appear.
- Hover (`textDocument/hover`) for configured projects, including unsaved buffers: a use shows its declaration's signature and, where it differs, as at a generic call, its type there; a declaration's name shows its signature; and a builtin use, such as `.length`, shows its type. Each text is a `virgil` code block in Markdown, or plain text for clients that don't accept Markdown. Hover shares go-to-definition's snapshot freshness, deferred replies, and position rules. See [Hover](docs/architecture.md#hover).
- The [occurrence index](docs/architecture.md#compiler-adapter) now covers layout references, the layout `L` in `Ref<L>` and a layout field's memory type, and packings and their parameters, with their declarations and their uses in packing expressions, including packing applications. Go-to-definition resolves them, and they carry display text for hover, such as `packing P(a: 4, b: 4): 8`. Not indexed: the letters of bit patterns, and `#packing` hints on variant cases, whose names the pinned compiler never resolves. ADR-0004 owns the worker protocol's [layout](docs/decisions/0004-analysis-worker-process.md#channel-and-framing).
- Release automation for tested server archives with checksums and exact build revisions. Each prerelease also attaches the VS Code extension's VSIX, packaged once, checked, and tested in the Extension Host against the release's Linux server before that same file is attached and listed in `SHA256SUMS`; the release notes give the extension's version. See [Releases](docs/releasing.md) for assets, platforms, publishing, dry runs, verification, and installation.
- Analyses now export the [display text](docs/architecture.md#display-text) that hover needs: each declaration's signature, the type of each use whose type differs from its declaration's, such as a generic call, the types of builtin uses, and the declaration at each name a file declares, whether or not anything uses it. The text is plain Virgil syntax, bounded in length and depth. The development `analyze --display` command prints it. ADR-0004 owns the worker protocol's [layout](docs/decisions/0004-analysis-worker-process.md#channel-and-framing) and the [result-budget measurements](docs/decisions/0004-analysis-worker-process.md#supported-program-size).
- VS Code extension packaging as a prerelease VSIX, with [manual installation](clients/vscode/README.md#installing-from-a-vsix) and [CI packaging and Extension Host checks](clients/vscode/README.md#development).
- Go-to-definition (`textDocument/definition`) for configured projects, including unsaved buffers and targets in open or closed files, using the semantic occurrence index. See [Definition](docs/architecture.md#definition) for supported uses, position lookup, snapshot freshness, and deferred replies.
- The [occurrence index](docs/architecture.md#compiler-adapter) now covers type references, type parameters, variant cases used as types, index operators, and construction of classes with descriptors. Builtin `Ref` no longer incorrectly targets its layout. Development [analysis statistics](docs/development.md#running) report skipped uses and charged result allocation; ADR-0004 owns the [worker protocol](docs/decisions/0004-analysis-worker-process.md#channel-and-framing) and [result-budget measurements](docs/decisions/0004-analysis-worker-process.md#supported-program-size).
- The server notices changes made outside the editor. It handles `workspace/didChangeWatchedFiles`: project files created, fixed, or deleted on disk republish their diagnostics, new project files are discovered, and sources created, changed, or deleted on disk update their projects and are analyzed again. It registers the watchers itself with clients that support dynamic registration, and the VS Code client also watches project files and sources. It advertises and handles workspace-folder changes. Clients without file events, such as Neovim 0.11 on Linux, keep refreshing projects on use. See [Changes on disk](docs/configuration.md#changes-on-disk).
- A project's `compilerArgs` now apply to its whole-program analyses and to parsing its open documents, so projects with flags such as `-lang:descriptors` get correct syntax diagnostics, document symbols, and semantic diagnostics. Projects with different flags share one analysis worker, and a configuration change republishes the syntax diagnostics it affects. See [Compiler flags](docs/configuration.md#compiler-flags).
- The editor clients send the Virgil root, so projects with `virgilDependencies` work: VS Code from the machine setting `virgil.virgilRoot` or else `VIRGIL_LOC`, and the Neovim configurations from `VIRGIL_LOC`. Both also send `.virgil-lsp.json` buffers, so configuration diagnostics follow unsaved edits, and VS Code now activates in workspaces that contain a project file. The planned `virgil.project.config` setting was dropped. See [The Virgil root](docs/configuration.md#the-virgil-root).
- Automatic semantic diagnostics for configured projects and unsaved buffers. See [Semantic diagnostics](docs/architecture.md#semantic-diagnostics) for scheduling, publication, freshness limits, failure recovery, and measurements.
- Bounded deterministic project source/dependency glob expansion on Linux and macOS, workspace-folder and nearest-config discovery, separate contexts for shared files, active-project selection, configuration diagnostics, and project-revision snapshot stamps. Project traversal never follows symlinks. See [Configuration](docs/configuration.md) for limits, ordering, and reload follow-ups, and [development stdio requests](docs/development.md#development-stdio-requests) for project submissions.
- VS Code development client in `clients/vscode/`: the `virgil` language for `.v3` files with comment and bracket configuration and a grammar written for this project, `virgil-lsp --stdio` started from `virgil.server.path`, startup checks and server stderr in a "Virgil Language Server" output channel, a trace setting, and a clean shutdown on deactivation. It runs on the workspace side for Remote-SSH and Remote-WSL. CI type-checks it and runs its lifecycle tests on Linux; see the [setup and manual checklist](clients/vscode/README.md) and the [supported versions](docs/compatibility.md#editors).
- Version 1 of the `.virgil-lsp.json` project file. [Configuration](docs/configuration.md) specifies its fields, patterns, Virgil library dependencies, accepted language options, and configuration diagnostics, and [ADR-0005](docs/decisions/0005-project-file-format.md) records the design. A parser under `src/workspace/` reports each problem with its location. Fixture projects are in `test/fixtures/projects/`.
- Server-side document version stamps for stdio analysis snapshots, with a freshness helper and recorded versions/currentness in the development inspection replies. See the [snapshot freshness policy](docs/architecture.md#analysis-snapshots-partly-present) and [development stdio formats](docs/development.md#development-stdio-requests).
- Headless Neovim smoke test of the documented plain configuration in both CI jobs. See [Neovim testing](editors/nvim/README.md#headless-smoke-test) for coverage and local usage.
- Asynchronous analysis workers in `--stdio` and unadvertised development requests for analysis and retained-snapshot inspection. See [development stdio requests](docs/development.md#development-stdio-requests) for request behavior and lifecycle cleanup.
- A replaceable analysis worker and [ADR-0004](docs/decisions/0004-analysis-worker-process.md), which records its process model and restart policy. See [Analysis worker](docs/architecture.md#analysis-worker) for the current integration scope.
- Single-file parser diagnostics for unsaved document overlays, with corrected comment offsets. See [Parser diagnostics](docs/architecture.md#parser-diagnostics) for publication behavior and [Compiler adapter](docs/architecture.md#compiler-adapter) for parsing and recovery details.
- Hierarchical VST-derived document symbols for open, unsaved buffers. See [Document symbols](docs/architecture.md#document-symbols) for supported declarations, ranges, and failure behavior.
- Versioned full-text document synchronization (`didOpen`, `didChange`, `didSave`, `didClose`) with exactly matching `initialize` capabilities. Stale/out-of-order changes, duplicate opens, and unsupported incremental changes are ignored and logged to stderr. In-memory overlays override disk through an injected reader, and local Linux/macOS file URIs are normalized to canonical keys. See [Document store](docs/architecture.md#document-store) for version, save, and URI identity rules. Unit and golden transcript tests cover synchronization and rejection sequences.
- `PositionMap` under `src/documents/`: coordinate conversion for document text. See [Coordinates](docs/architecture.md#coordinates) for supported encodings, line endings, and out-of-range handling.
- LSP lifecycle and `$/cancelRequest` notification handling. See [Lifecycle](docs/architecture.md#lifecycle) for initialization, shutdown, cancellation, and exit behavior.
- Golden transcript tests under `test/protocol/`: recorded `--stdio` input bytes with the expected output bytes and exit status, covering the lifecycle, fragmented, consecutive, malformed, Unicode, and oversized messages, and cancellation. `make test` runs them.
- Pending-request table and response matching for server-initiated requests. See [Server requests](docs/architecture.md#server-requests) for the completion contract, logging, and current limitations.
- `--stdio` transport: reads framed messages from standard input, dispatches them, and writes framed output to standard output, handling partial writes. `--max-message-bytes=<n>` sets the payload limit within the [supported memory budget](docs/architecture.md#framing). Skipped messages are logged to stderr. A malformed header, a failed write, or input that ends inside a message exits with status 1.
- LSP base-protocol frame reader: `Content-Length` counted in bytes, input split at any point, optional `Content-Type` with a UTF-8 charset (semicolons inside quoted parameter values don't separate parameters), a configurable payload limit that skips longer messages, incremental payload buffering and release of oversized staging buffers, and a bounded header. See [framing limits and buffering guarantees](docs/architecture.md#framing). A header without a valid `Content-Length` stops the stream.
- JSON-RPC 2.0 message model under `src/protocol/`: distinct request, notification, response, and error-response shapes; integer and string IDs echoed in replies; `params` absent, object, array, or null. See the [dispatch contract](docs/architecture.md#json-rpc-messages) and [lifecycle](docs/architecture.md#lifecycle) for notification handling and request errors.
- JSON parsing and rendering on top of Virgil's `lib/file/json`, with fixes for string escapes, carriage returns, numbers that aren't 32-bit integers, deep nesting, messages with more values than the heap can hold, and invalid JSON output. See [JSON limits](docs/architecture.md#json-limitations-and-workarounds) for admission rules.
- Whole-program analysis in the Aeneas adapter: in-memory sources are parsed and verified as one program (no initialization or code generation). Syntax and semantic errors come back as `AnalysisDiagnostic`s, and a verified use can be followed to its declaration.
- Development command `analyze` (with `--bindings`, `--stats`, `--repeat=<n>`) and `scripts/bench-analysis.sh`.
- ADR-0003: supported platforms are Linux x86-64 and macOS on Apple Silicon (Rosetta 2 for now). WSL 2 was supported at first and is best effort since the ADR's 2026-10-20 amendment.
- macOS CI job on an Apple Silicon runner, and macOS in the weekly Virgil-master check.
- Repository foundation: Apache-2.0 license, roadmap, community documents, issue and pull-request templates, and CI.
- ADR-0001 (Virgil-native server) and ADR-0002 (pinned Virgil adapter boundary).
- Pinned Virgil submodule at `9945e430` and a `make`-based build that compiles against it.
- `virgil-lsp` executable with `--version`, `--help`, and a development `parse` command that reports Aeneas syntax diagnostics.
- Unit tests for the Aeneas adapter and command-line smoke tests.

### Changed

- WSL 2 on x86-64 Windows is best effort: the Linux build is expected to run there but isn't tested ([compatibility](docs/compatibility.md#host-platforms)).
- Analysis results carry exact UTF-8 byte offsets for every declaration and occurrence, and snapshots look up uses by byte offset. Result allocation charges are unchanged. See [Coordinates](docs/architecture.md#coordinates) and ADR-0004's [supported program size](docs/decisions/0004-analysis-worker-process.md#supported-program-size).
- Pinned Virgil moved from `9945e430` to [`7cf038fc`](https://github.com/titzer/virgil/commit/7cf038fc13a5474836bec8b14c7a3e796fd07fa5) (2026-10-08). The server and worker now include upstream's garbage-collector fix for forwarding pointers in 64-bit heaps above 4 GiB, where the macOS build's heap lives. The compiler front end is unchanged, so diagnostics, bindings, and document symbols are identical.
- The development `analyze` command now uses the analysis worker, with timeout and analysis-count tuning options; see [Running](docs/development.md#running) for options and failure output. `make` also builds `build/virgil-lsp-worker`; see [Building](README.md#building) for executable placement.
- Analysis adapter caches a lazy per-file binding index and binary-searches definition queries, reuses compiler configuration across analyses, and counts the global type cache only for requested statistics. The development `analyze --bindings` command reuses its report buffer without copying each file's output.

### Fixed

- Whole-program parsing is about ten times faster again, after exact diagnostic byte ranges had made it about 13 times slower. Semantic diagnostics for a program the size of the Aeneas sources now arrive about 220 ms after a save instead of about 830 ms, and the analysis worker's peak memory falls from 385 MiB to 336 MiB. Parser diagnostics and document symbols for large open files are also faster. See [Coordinates](docs/architecture.md#coordinates).
- Over-budget analysis results now report that the program is too large rather than blaming a malformed worker. See ADR-0004 for the [replacement policy](docs/decisions/0004-analysis-worker-process.md#restart-policy) and [supported program size and recovery guidance](docs/decisions/0004-analysis-worker-process.md#supported-program-size).
- Parser diagnostics and document symbols no longer kill the server on an expression statement that chains tens of thousands of operators or suffixes, such as `1 + 1 + … + 1;`. Whole-program parsing shares this guard. See [Aeneas crash paths](docs/aeneas-crash-paths.md) for the chain limit and recovery behavior.
- Parser diagnostics and document symbols now contain deep parser nesting and the remaining malformed-range traps. See [Aeneas crash paths](docs/aeneas-crash-paths.md) for the recovery behavior and containment limits.
- Document symbols no longer kill the server on expression-start `...` or `..+` (for example, while typing `xs[...]`); the outline now shares the parser driver and recovery used for parser diagnostics. See [Document symbols](docs/architecture.md#document-symbols).
- Whole-program diagnostics now retain exact UTF-8 byte ranges through the analysis worker, including tabs in block comments, trailing line-comment EOF errors, and multi-byte source text. Compiler display coordinates remain available for CLI reports.
- Whole-program analyses no longer leave verified programs rooted in Aeneas's global type cache or its superseded, statically allocated bucket arrays. Dropped snapshots return close to the pre-analysis live-heap baseline; a fresh-process regression covers repeated analyses and error paths. See [compiler constraints](docs/architecture.md#known-constraints-of-the-compiler-front-end).
- Occurrence collection reports uses only once in default match cases, lambda bodies (including nested lambdas and field initializers), and superclass arguments shared with constructors.
- Match-case names and enum parameter fields now resolve in the [occurrence index](docs/architecture.md#compiler-adapter).
- Bound aggregate open-document overlays and warn clients when admission is rejected. See [Document store](docs/architecture.md#document-store) for the supported capacity, recovery policy, and parsing headroom.
- Corrected binding queries that targeted compiler-synthesized declarations or treated inline exports as uses. See the [binding contract](docs/architecture.md#compiler-adapter).
- Occurrence collection no longer traps on a null type binding left by verification errors, including `E.set.all` on enums with more than 64 cases.
- `scripts/bench-analysis.sh` reports failed input sets, command exit statuses and stderr, rejects runs without timing samples, and cleans up temporary files on exit.
